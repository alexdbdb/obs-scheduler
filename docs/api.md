# Local API v1

Settings → API → Regenerate token; copy the token once. Enable API and save. Default URL `http://127.0.0.1:8766`; Bearer authentication is required for every defined route. No browser CORS support. The API creates and edits recording schedules and requests calendar refresh; OBS's own controls remain the place for manual recording. Keep the token private. Only loopback addresses are accepted, even if an older configuration acknowledged network exposure. On upgrade, the API host migrates to 127.0.0.1. HTTPS and remote network control are not supported.

| Method | Path | Result |
| --- | --- | --- |
| GET | /api/v1/status | Version, scheduler flag, OBS states |
| GET | /api/v1/events | `{ "events": [...] }` |
| GET | /api/v1/events/{id} | Event |
| POST | /api/v1/events | Create API event, HTTP 201 |
| PUT | /api/v1/events/{id} | Replace writable event, HTTP 200 |
| DELETE | /api/v1/events/{id} | Delete writable event or persistently hide an imported event locally |
| POST | /api/v1/sync | Start provider refresh, HTTP 202 |

```sh
curl -X POST http://127.0.0.1:8766/api/v1/events \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"title":"Artist X","start":"2026-09-10T21:00:00+02:00","end":"2026-09-10T23:00:00+02:00","enabled":true}'
```

On PowerShell use `curl.exe` and preferably `--data-binary @event.json` to avoid shell JSON quoting differences. The response supplies the ID for subsequent GET/PUT/DELETE. PUT is a full replacement: include title/start/end and the other fields you want retained. POST always creates a fresh ID; API clients needing idempotent updates must retain the returned ID and use PUT. Imported events reject PUT, but DELETE creates a persistent local exclusion and returns `"local_only": true`; it does not delete the source calendar event. Recurring events return 409 for mutation. Do not send external_id/source/source_calendar to impersonate providers; those are server-controlled. Dates with an explicit offset preserve that instant; local UI and recurrence times use the OBS device timezone.

Errors use `{ "error": "clear message" }`: 400 validation/invalid JSON, 401 missing/invalid token, 403 browser Origin, 404 missing event, 405 unsupported method, 409 read-only source, 413 application body limit, 500 internal failure. Recording transitions are generated by schedules and confirmed through history and OBS diagnostics.

The API never edits credentials or server configuration; those remain local UI operations. Token regeneration invalidates the previous token. See [OpenAPI](openapi.json) for a machine-readable description.
